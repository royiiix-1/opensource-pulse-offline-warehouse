# 设计取舍

## 为什么保留 raw 和 ODS 原文

源事件包含异构 payload 和未来新增字段。保留原始文件与 raw_json，使 schema 变更可以回溯重建；source SHA 与 line_number 提供记录级血缘。

## 为什么使用版本指针

独立候选目录与数据库让失败写入不影响旧结果。质量检查及元数据位置复核之后，原子替换指针，避免把半成品暴露给受控读取入口。该方案适合本地实验，不宣称跨系统事务或多主控制器。

## 去重和异常

相同 event_id、相同原文去重并留审计；冲突原文阻断发布。未知类型保留到 unknown 分支，坏行进入 quarantine，默认零坏行门槛。可选 payload 缺失保留 null，不以零填补未知值。

## SCD2

repo_id 为自然键；属性限定为观察到的 repo_name/owner_name。连续同名不产生版本，改回旧名仍生成新版本。同一观察时间出现冲突名称时拒绝维度发布。当前使用选定日期快照重建，未实现任意历史窗口的全局增量合并。

## 指标

PR closed 与明确 merged 分开；commit 声明计数与可见数组长度分开。owner 的 distinct actor 从 DWD 独立计算，不能累加仓库级 distinct。留存 cohort 是样本中首次观察活跃周，两周覆盖都完整才成熟。

## 内存和文件布局

宽 JSON 写出曾发生排序内存不足。磁盘缓存与较小 Parquet 行组组成的配置在相同真实数据上完成恢复，没有增加 executor 内存。writer 阈值 1 仍会回退排序，不声称免排序成功。

性能布局不追求单一答案：日级压实减少文件数、改善该全日查询，但小时过滤更适合小时分区，且压实文件总字节增加。所有结论限定于已保存的本机重复实验。
